# Self-improvement Role Redesign Plan

> **For Hermes:** Implement this plan in small TDD slices. Do not preserve old role or observation compatibility. Update tests and docs to the new model instead of keeping shims.

**Goal:** Redesign the self-improvement plugin around four first-class roles (`planner`, `editor`, `evaluator`, `calibrator`) and a local turn-trace evidence pipeline that feeds the planner without adding another LLM role.

**Architecture:** Collapse the old `target_resolver + improvement_planner + skill_agent + memory_agent + evaluator` model into a simpler core. `planner` owns observation interpretation and transaction planning, `editor` owns all knowledge mutation, `evaluator` owns quality scoring, and `calibrator` owns GEPA-based prompt optimization. Observation data is stored as local Langfuse-style turn traces, then mechanically normalized into cluster indexes and drilldown details. Keep deterministic code for trace collection, evidence indexing, schema validation, hard preflight checks, verification, and artifact persistence.

**Tech Stack:** Hermes plugin CLI, Python, pytest, existing self-improvement artifacts/config/prompt overlay runtime.

## Decisions

### Observation model

Track complete agent turns, not isolated LLM/tool hook rows. Use the bundled Langfuse plugin as an implementation reference for span shape and safe serialization, but do not send traces to Langfuse and do not require the Langfuse SDK.

```text
Level 0: raw turn trace
  Full local trace artifact for each turn. Normally not passed to planner.

Level 1: cluster summary
  Deterministic grouping across traces. Stores all clusters with counts, outcomes, tools, targets, and representative turn ids.

Level 2: evidence index
  Compact cluster list passed to planner, like `skills_list` for observations.

Level 3: evidence detail
  Planner can request detail for selected clusters, like `skill_view` for observations.
```

The observation pipeline must not add an LLM summarizer role. Cluster lists and details are generated by code from structured trace fields. Semantic decision-making belongs to `planner`.

### Final role model

```text
planner
  LLM reads observation evidence and produces a transaction plan.

editor
  LLM edits skills, MEMORY.md, USER.md, and provider-backed memory through official tools.

evaluator
  LLM evaluates candidates, before/after diffs, execution results, and prompt candidates.

calibrator
  GEPA/optimizer loop uses evaluator results to improve planner/editor/evaluator prompt overlays.
```

### Role boundaries

#### planner

Responsibilities:
- Read compact observation/evidence bundles.
- Classify signals as `skill`, `memory`, `user_profile`, `noise`, or `unresolved`.
- Decide whether the right outcome is `apply`, `skip`, `defer`, or `block`.
- Produce a bounded transaction plan for the editor.
- Handle the old resolver responsibility: target attachment, unresolved classification, and skill/memory/user-profile routing.
- Use deterministic helpers for evidence lookup, target normalization, and provenance facts; planner makes the semantic decision but does not re-derive raw inventory facts.

Does not:
- Mutate skills or memory.
- Call mutation tools.
- Run GEPA.

#### editor

Responsibilities:
- Execute planner-approved transaction plans.
- Patch/create skills.
- Add/replace/remove memory entries.
- Move content between `MEMORY.md`, `USER.md`, and skills when appropriate.
- Use add-before-remove semantics for cross-store moves.
- Verify that a mutation actually happened before reporting success.

Does not:
- Re-plan broad strategy from scratch.
- Mutate targets outside the planner transaction.
- Directly edit memory files or provider databases when official tools exist.

#### evaluator

Responsibilities:
- Score planner decisions, editor mutations, before/after quality, no-op correctness, and reporting evidence.
- Produce structured evaluation records usable by reports and calibrator.
- Keep rubric stable enough that calibrator results are interpretable.

Does not:
- Mutate runtime prompts directly.
- Execute skill or memory changes.

#### calibrator

Responsibilities:
- Use GEPA or equivalent optimizer to improve `planner`, `editor`, and `evaluator` prompt overlays.
- Consume representative eval cases and evaluator/rubric results.
- Promote prompt overlays only when they beat the current baseline under configured gates.
- Use a frozen evaluator rubric and fixed benchmark case set for promotion decisions in a calibration run.

Does not:
- Run as part of every lightweight improve pass.
- Mutate knowledge stores.
- Self-improve its own optimizer policy in this redesign.

---

## Non-goals

- Do not keep legacy role names as first-class runtime roles.
- Do not preserve old apply/ledger-era compatibility paths. Rewrite tests/docs to the new model instead of maintaining shims.
- Do not add a new approval lane, queue, policy engine, or scoring subsystem.
- Do not make calibrator self-referential yet. Calibrator prompt/policy remains versioned and manually changed.
- Do not add an LLM-based evidence summarizer. Evidence summaries are mechanical and structured; planner does the meaning-making.
- Do not preserve legacy observation formats as first-class inputs. No dual hook-row/event pipeline and no runtime import path. The new runtime model is only turn trace -> cluster summary -> evidence index/detail.
- Do not discard non-selected traces or clusters. Planner sees a budgeted index, but raw traces and full cluster summaries remain available for audit and drilldown.

## Target behavior

### Normal improve run

```text
local turn traces
  -> deterministic trace normalizer
  -> deterministic cluster builder
  -> evidence_index
  -> planner
  -> planner may call evidence_view(cluster_id)
  -> deterministic schema validation + hard preflight
  -> editor
  -> deterministic verification
  -> evaluator
  -> compact artifacts/report
```

### Calibration run

```text
representative cases
  -> evaluator/rubric
  -> calibrator/GEPA
  -> planner/editor/evaluator overlay candidates
  -> gated promotion
```

### Planner evidence access

The planner receives an evidence index, not raw trace bodies. The index should be compact enough to fit in the planner prompt while preserving breadth.

```text
evidence_index
  cluster_042 | tool_failure | skill_view/ambiguous_skill_name/recovered
  count=84 recent=12 unrecovered=3 targets=timeout-workflow,safe-patch-usage
  signals=ambiguous_skill_name,qualified_retry_succeeded,occasional_unrecovered_final

evidence_view(cluster_042)
  cluster stats
  representative turns
  tool/LLM loop summaries
  recovery and final-outcome labels
  artifact refs
```

This mirrors Agent Skills: list first, view details only when the LLM decides an item matters.

Planner can only access structured evidence index/detail records. Raw trace bodies and original artifacts are audit/debug material, not planner context.

**Tests:**

- Old role names are not required for status to be healthy.

### Slice 2: Introduce planner output schema

**Objective:** Make the planner the single place where resolver/planner decisions are represented.

**Planner output shape:**

```json
{
  "decision": "apply|skip|defer|block",
  "target_store": "skill|memory|user_profile|none|unresolved",
  "target_id": "optional skill name or memory identifier",
  "source_store": "skill|memory|user_profile|external_memory|none",
  "source_id": "optional source identifier for replace/remove/move actions",
  "reason": "short explanation",
  "editor_task": {
    "action": "patch_skill|create_skill|add_memory|replace_memory|remove_memory|move_memory_to_skill|move_user_memory|none",
    "instructions": "bounded editor instructions",
    "source_evidence_ids": ["..."],
    "preconditions": ["..."]
  }
}
```

**Work:**
- Add/adjust dataclass or Pydantic/schema validation for planner decisions.
- Normalize invalid combinations:
  - `decision != apply` -> `editor_task = null`
  - `target_store = unresolved` -> no editor mutation
  - no evidence -> no editor mutation
- Enforce this minimal action matrix:
  - `decision=apply` with `target_store=skill` permits `patch_skill`, `create_skill`, `move_memory_to_skill`.
  - `decision=apply` with `target_store=memory` permits `add_memory`, `replace_memory`, `remove_memory`, `move_user_memory`.
  - `decision=apply` with `target_store=user_profile` permits `add_memory`, `replace_memory`, `remove_memory`, `move_user_memory` against `target=user`.
  - `decision=skip|defer|block` permits no editor task.
  - `target_store=none|unresolved` permits no editor task.
- Require `source_store` and `source_id` for replace/remove/move actions.
- Keep hard preflight small: pinned/protected target, unresolved target, non-local skill provenance, missing old_text for replace/remove.

**Tests:**
- Planner can choose skill, memory, user_profile, unresolved, noise/skip.
- `skip/defer/block` cannot carry mutation instructions.
- Unresolved target stops before editor.
- Replace/remove/move actions without `source_store` and `source_id` are rejected before editor.

### Slice 3: Add local turn trace collector

**Objective:** Store complete turn-level traces locally using the Langfuse plugin's hierarchy as the reference shape.

**Trace shape:**

```text
Hermes turn
  - metadata: trace_id, session_id, task_id, platform, provider, model, started_at, ended_at
  - input: user message hash + short preview
  - spans:
      - LLM call N: finish_reason, usage, duration, requested tool calls
      - Tool call: tool_name, args summary, result summary, error kind, duration
  - final: response hash + short preview, completed/interrupted/timeout labels
```

**Work:**
- Reuse the Langfuse plugin's useful ideas: `TraceState`, root turn span, child LLM/tool spans, session id propagation, safe truncation, read-file payload normalization, and fail-open hook behavior.
- Do not depend on Langfuse SDK or network services.
- Store redacted local artifacts under the self-improvement runtime directory.
- Keep hook work cheap: collect/append only, no LLM calls, no GEPA, no skill/memory mutation.
- Clean up in-memory trace state on completed, interrupted, failed, and timed-out turns.
- Keep trace state keyed by turn/task identity so parallel turns cannot mix spans.

**Tests:**
- A turn with two LLM calls and one tool call creates one trace with nested spans.
- Tool errors and recovered retries are represented in the same turn trace.
- Large tool results and `read_file` payloads are truncated/normalized.
- Missing/failed trace writes do not break the agent turn.
- Interrupted/failed/timed-out turns do not leave stale trace state behind.
- Parallel turns keep separate trace state.

### Slice 4: Build deterministic evidence index and detail views

**Objective:** Convert raw traces into planner-readable cluster indexes and drilldown details without using an LLM summarizer.

**Cluster key v1:**

```text
signal_kind + tool_name + error_kind + normalized_target + outcome
```

Examples:

```text
tool_failure | skill_view | ambiguous_skill_name | timeout-workflow | recovered
tool_failure | terminal | timeout | self-improvement-maintenance | unrecovered
memory_signal | repeated_user_preference | placement | response_style | unresolved
skill_gap | loaded_skill_missing_step | timeout-workflow | n/a | recovered
```

**Evidence index item:**

```json
{
  "schema_version": 1,
  "id": "cluster_042",
  "category": "tool_failure",
  "pattern_key": "skill_view/ambiguous_skill_name/recovered",
  "count": 84,
  "recent_count_24h": 12,
  "first_seen": "...",
  "last_seen": "...",
  "outcome": {"recovered": 81, "unrecovered": 3},
  "tools": ["skill_view"],
  "targets": ["timeout-workflow", "safe-patch-usage"],
  "signals": ["ambiguous_skill_name", "qualified_retry_succeeded", "occasional_unrecovered_final"],
  "representative_turn_ids": ["turn_a", "turn_b", "turn_c"]
}
```

**Representative turn selection:**
- latest unrecovered;
- highest severity;
- most common recovered;
- first seen;
- latest seen.

Tie-breaks must be deterministic: severity desc, unrecovered desc, recent timestamp desc, count desc, cluster id asc, turn id asc.

**Work:**
- Build all cluster summaries and persist them.
- Build a planner evidence index using budgeted selection over clusters.
- Preserve omitted cluster counts and omission reasons for audit.
- Add an `evidence_view(id, depth=cluster|turns)`-style internal access path for planner drilldown. Raw trace artifacts stay audit-only unless a human/debug command reads them.

**Tests:**
- All traces are retained even when not selected for the planner index.
- Similar recovered tool failures cluster together.
- Unrecovered failures remain visible even if less frequent.
- The planner index contains compact structured items, not LLM-written summaries.
- `evidence_view` returns stable structured detail for a selected cluster.
- Same input traces produce byte-stable cluster ids, ordering, representative turns, and evidence index output.

### Slice 5: Connect planner to evidence index/detail

**Objective:** Make planner consume the evidence index and request detail for important clusters instead of receiving raw observations.

**Work:**
- Replace raw observation bundles in planner input with the evidence index.
- Add a controlled detail access surface for the planner.
- Record which evidence ids the planner viewed and which ids drove the final transaction plan.
- Keep planner responsible for semantic classification: `skill`, `memory`, `user_profile`, `noise`, or `unresolved`.
- Reject planner detail requests for raw artifact bodies or ids outside the current evidence index/detail set.

**Tests:**
- Planner can produce a transaction plan from index-only evidence.
- Planner can request cluster detail and cite viewed evidence ids.
- Planner can skip/no-op a high-frequency cluster when detail shows it is fully recovered/noise.
- Planner does not require raw trace access for normal operation.
- Planner cannot request arbitrary raw trace ids or raw artifact bodies.

### Slice 6: Merge skill and memory editors

**Objective:** Replace separate skill and memory agents with one knowledge editor.

**Work:**
- Create one editor prompt that has both responsibilities.
- Give editor access to official skill and memory mutation surfaces only.
- Execute exactly the planner transaction, not a broad autonomous search.
- Implement cross-store move ordering:
  1. write/patch/create destination;
  2. verify destination;
  3. remove/replace source only after success.

**Tests:**
- Existing skill patch still works.
- New skill creation still works when planner requests it.
- Memory add/replace/remove still works.
- `MEMORY.md -> skill` move does not remove source if skill mutation fails.
- `USER.md <-> MEMORY.md` move is add-before-remove.

### Slice 7: Keep evaluator separate and update evaluation inputs

**Tests:**

## Acceptance criteria

- The only first-class self-improvement roles are `planner`, `editor`, `evaluator`, and `calibrator`.
- Planner owns all target resolution and planning.
- Editor owns all skill/memory/user-profile mutation.
- Evaluator remains independent.
- Calibrator optimizes planner/editor/evaluator prompts, not itself.
- Old compatibility paths are removed; tests and docs use the new model only.
- `status`, `report`, `improve --dry-run`, and `calibrate --dry-run` all work with the new role names.
- Daily maintenance no longer spends work on obsolete role targets.
- Observation is turn-trace based rather than isolated hook-row based.
- Planner receives a compact evidence index and can drill into selected cluster details.
- Evidence index/detail generation is deterministic and does not introduce another LLM role.
- Non-selected traces and clusters are retained for audit and future runs.
